# 決済まわりの取り決め

このツールは全機能が無料。そのうえで、**すでに使ってもらったことへの
任意のお礼（チップ）だけ**を受け付けている。
この文書は「一度なぜ止められたか」と「どう戻したか」を残すためのもの。

## いまの状態

| 項目                                   | いま                                                          |

## 経緯

### 2026-08-13 — 最初の照会

Stripe から「クラウドファンディング・資金調達・寄付募集に関連しているようだ」
という照会が入った。原因は、応援ページに置いていた次の言いかた。

> 応援が、次のフレームになります
> 次に何をつくるかは、まだ決めていません
> いただいた応援は、新しいアイコンフレームの制作や、このツールの改善に活用させていただきます

**これから作るものへのお金集め**と読める。Stripe の判断は妥当だった。

Stripe がチップに求めるのは「**すでに提供した商品・サービスに対する任意の支払い**」であること。
将来の成果物に触れた瞬間、それは資金調達になる。

皮肉なことに、この書きかたは特定商取引法の表示義務を避けるために選んだものだった
（対価がなければ販売ではないので、住所や電話の公開が要らない）。
片方を満たす言葉が、そのままもう片方に当たった。

### 対応で踏んだ穴（同じ轍を踏まないために）

1. **画面から消しただけでは足りない。**
   募集の文言を条件分岐の向こうに置いた。描画はされないが、**文字列は配られる JS に
   そのまま残っていた**。審査を受けている当のアカウントで、引っかかった当の文言が
   公開物から読み出せる状態だった。
   → 画面を見る検証では捕まえられない。**ファイルそのものを読む**必要がある。

2. **タブの名前も画面のうち。**
   本文が「受け付けを止めています」と言っているのに、タブは「制作活動を応援する」のままだった。
   条件分岐の向こうではなく、実際に表示されていた。

3. **文言より、順路のほうが目立っていた。**
   ページのいちばん上に「支援をえらぶ → 決済する → 完了」という帯が残っていた。
   公開後のスクリーンショットで見つかった。
   検証が捕まえられなかったのは、**「何が出ていないか」を一度も数えていなかった**から。

### 2026-08 — 審査完了

追加情報を提出し、審査は完了。そのうえで、決済まわりを丸ごと外した。
再開の予定はあるが、**Stripe への事前確認が済むまでは戻さない**。

戻すときの手順は `docs/tip-restart-plan.md` にある（何を、どの順番で、誰がやるか）。

### 2026-08 — 戻した

Stripe に事前確認（この用途で可、という回答）。決済リンクを1本つくり、
`TIP_URL` に入れて公開した。実機で入口・断りの文・決済画面・金額の変更まで確認ずみ。

### 2026-08 — 掲載文面を1行足した（承認のあと）

チップを公開したあと、決済画面が **500円を大きく出し、「金額を変更」は小さい**
ことが分かった。初見では500円を払う画面に見え、100円送りたい人はあきらめ、
1000円送りたい人は気づかない。**両方向に取りこぼす。**

そこで掲載文面に1行足した。

```
（前）金額を決める画面と支払いは、決済サービスの側でおこないます。
（後）金額は次の画面で自由に変更できます。
      金額の設定と支払いは、決済サービスの側でおこないます。
```

**Stripe に出した文面を、承認のあとに変えている。** これは本来いちばん避けたい形なので、
なぜよしとしたかを残す。

- 足したのは**実際の挙動の説明**であって、用途の変更ではない。
  問い合わせの時点で「金額は利用者が決めます」と説明しており、
  その説明を画面にも書いただけ。
- 見返り・将来の成果物・金額・使いみち、どれにも触れていない。
- 金額の数字は書かない。値段表に見えはじめるうえ、決済側の設定を変えたときに
  黙って食い違う。

**次に文面を変えるときも、ここに前後を残す。** 3か所（画面・手順書・問い合わせ文）が
そろっていることは検証が見ているが、**「いつ・なぜ変えたか」は検証では残らない。**

## 戻すときの条件

**この文書の禁止語リストを消して通す、ということをしない。**
リストに当たらない文章を書く。

### 満たすこと

1. **Stripe に事前に確認を取る。**
   一度「規制対象業種のいずれかに関連する」と判断されたアカウントなので、
   黙って再開しない。何を売るのかを説明し、承認を得てから。

2. **「すでに提供したものへの任意の謝礼」として書く。**
   将来の成果物・制作予定・使いみちに触れない。
   見返り（特典・限定・先行）を約束しない。
   目標金額・募集期間・支援者一覧を置かない。

3. **払わない人が損をしない。**
   支払いは全機能の利用条件にしない。払っても機能は1つも変わらない、と書く。

4. **特定商取引法の表示義務を確認する。**
   対価性が生まれる書きかたにすると、表示義務が発生する。
   1と2を満たす書きかたはこの義務を避けられるが、**避けるために将来の成果物へ
   逃げると Stripe に当たる**。この2つは同時に満たす必要がある。

### 使ってはいけない表現

`tools/check-dist.mjs` の `BANNED_WORDS` が正。抜粋：

```
制作活動応援 / 制作活動を応援 / 制作活動を続けていけます
応援が、次のフレームになります / 次のフレームになります
新しいアイコンフレームの制作 / 新しい表現を試すための制作
このツールの改善に活用 / まだ決めていません / creator_support
```

決済リンク（`buy.stripe.com` / `checkout.stripe.com` / `donate.stripe.com`）も同様に禁止。

## 見張りかた

```
npm run build && npm run check:dist    # 配るものを直接読む
npm test                               # 通しの検証（上の点検も含む）
```

`tools/check-dist.mjs` が見ているもの:

1. 資金集めに読める文言が入っていないか
2. 決済リンクが、**決めた1本のほかに**入っていないか
   （送り先が空のビルドなら0本。数えかたを状態で切り替えている）
3. お礼の文言が、出すと決めた状態と合っているか
   （空のビルドには1つも入っていない／入りのビルドには全部そろっている）
4. 画面に出るお礼の文面が、Stripe に出した文面と同じか
   （手順書と問い合わせ文の2か所。書き換えても、1行消しても落ちる）
5. 秘密鍵（`sk_` / `rk_` / `whsec_`）が入っていないか
6. 誰からも参照されていない古いハッシュ付きファイルが残っていないか

6 は残りかすの話。`--emptyOutDir` を付け忘れたビルドや手で足したファイルがあると、
古い JS が公開先に残る。中身が古いので、**消したはずの文言がそこから生き返る**。

あわせて、配るものの重さも見ている（gzip したあとの KB）。
スマホしか持っていない人が前提の道具なので、1回ごとに気づける場所を作ってある。
**超えたら、上限を上げる前にまず中身を疑う。**

通しの検証（`tests/run.mjs`）では、画面の側からも見ている。

- **つくる画面が、お礼の入口の有無で1文字も変わらないこと**（これがいちばん大事）
- つくる・知らせるの両方に、お金に触れる要素が無いこと（出ていてはいけないものを数える）
- お礼の画面に、危ない言いかた（寄付・支援・特典など）が出ないこと
- 押すと、決めた送り先だけが開くこと
- 古いURL（`#/support` / `#/support/thanks` / `?thanks=1`）が知らせるページへ送られ、
  URL も置き換わること

## 公開の順番

**コードを直してからではなく、サイトを直してから申告する。**

1. `npm run build && npm test` を通す
2. GitHub Pages へ反映する
3. 実際の公開URLを開いて、目で確かめる
4. そのうえで Stripe へ出す

逆にすると、審査中に古いものを見られる。実際に一度、この順番を誤って
サイト側の直しが1つ足りないまま送りかけた。
