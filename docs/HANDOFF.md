# 引き継ぎ書

このリポジトリを、別の人（あるいは別のAI）が引き継いで作業するための資料です。
**README は「何を作ったか・なぜそう作ったか」、この文書は「どう触るか」**を書いています。
はじめて触るときは、この文書を上から読んでから README に進んでください。

---

## 1. 30秒でわかる全体像

ブラウザだけで動く、背景透過の道具です。**画像も動画も、端末の外に出しません。**
サーバーはありません（GitHub Pages に置く静的なファイル一式）。

道具は2つあり、URL で分かれています。

| 画面     | URL        | 何をするか                                                   |
| -------- | ---------- | ------------------------------------------------------------ |
| つくる   | `#/`       | アイコンフレームの背景を消して、プロフィール写真に重ねて保存 |
| スタジオ | `#/studio` | **動画と画像**の背景を消して、配信・編集アプリ向けに書き出す |
| 知らせる | `#/share`  | 人に紹介するだけのページ                                     |

想定している使い手は「スマホしか持っていない、TikTok を使っている人」です。
この前提が、重さの上限・言葉づかい・ボタンの出しかたの全部に効いています。

## 2. まず動かす

```bash
npm ci
npm run dev        # 開発サーバー
npm run build      # dist/ を作る（typecheck も走る）
npm test           # 実ブラウザでの通し検証（先に build が要る）
```

**検証は Chromium を起動して 8〜10分かかります。** 途中経過は出ますが、
最後の1行（`全 N 件 合格`）まで待ってください。

### この開発環境の癖（ハマりどころ）

| こと             | 実際                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| Chromium の場所  | `CHROMIUM_PATH=/opt/pw-browsers/chromium-*/chrome-linux/chrome npm test` |
| H.264（MP4）の鍵 | **検証用 Chromium には入っていない。** MP4 は再生も復号もできない        |
| huggingface.co   | **遮断されている。** AI 切り抜きはこの環境では一度も動かせない           |
| ffmpeg           | 入っていない。必要なら `pip install imageio-ffmpeg` で取ってくる         |
| 整形             | `npx prettier --write` は**必須**（検証には無いが、差分が汚れる）        |

この制約があるので、**検証用の動画はブラウザ自身に録らせています**
（`MediaRecorder` で WebM を作り、`DragEvent` で画面に落とす）。
リポジトリに動画を置かない理由でもあります。

## 3. 触る前に知っておくこと（変えてはいけない約束）

破ると、この道具の意味が無くなるものです。

1. **画像・動画は端末から出さない。** 通信するのは AI モデルを取りにいくときだけ。
   アップロードする実装は、どんな理由でも入れない。
2. **見えている絵と、保存される絵を1ピクセルも違わせない。**
   - 透明を表す市松もようは CSS の背景。`<canvas>` の中には描かない
   - 舞台（プレビュー）の上に効果（ビネット・粒子）をかけない
3. **いま押すボタンは、画面に1つ。** 色が付いた大きなボタンを2つ出さない。
4. **専門用語を出さない。** 「アルファチャンネル」「マスク」「クロマキー」は
   画面に出しません（「透明」「消す」「緑を抜く」と書く）。
   保存の行き先も、形式名ではなく**使う場所の名前**で並べます。
5. **配るものの重さに上限がある。**（`tools/check-dist.mjs`）
   - 本体 JS 95KB / 本体 CSS 12KB（どちらも gzip 後）
   - **スタジオは遅延読み込み**（`Root.tsx`）。静的に import すると上限を割ります
6. **資金集めに読める文言を入れない。**（禁止語の一覧は `tools/check-dist.mjs`、
   経緯は `docs/stripe-compliance.md`）。検証はリポジトリ全体を読んで確かめます。
7. **コメントは「なぜ」を日本語で書く。** 何をしているかはコードが言うので、
   コメントには**その形にした理由**と、**やってみて駄目だったこと**を書きます。
   このリポジトリのコメントは、そのつもりで読むと設計資料になります。

## 4. コードの地図

詳しい説明は README の「中身の地図」にあります。ここは要点だけ。

```
src/lib/cutout.ts      背景透過の中身（自動判定・色キー・フチ処理・手描き・合成）
src/lib/ai.ts          transformers.js での切り抜き（動的 import 専用）
src/lib/video/         スタジオの中身
  mp4.ts               MP4 をほどく（WebCodecs にわたすため）
  source.ts            コマの取り出し（WebCodecs ／ <video> の2通り）
  matte.ts             マットの保持・ゆれ止め・仕上げ・絵の組み立て
  glow.ts              黒い地の光ものを、明るさから抜く（DOM を触らない）
  budget.ts            いちどに引き受ける長さの計算（DOM を触らない）
  pipeline.ts          消しかたの決定と、コマごとの処理の進行
  export.ts            透過WebM・グリーン・PNG連番・背景つきの書き出し
  zip.ts               無圧縮 ZIP（依存なし）
src/components/studio/ スタジオの画面（StudioPage / Stage / FilmStrip / SaveSheet）
```

**`glow.ts` と `budget.ts` は DOM を触りません。** Node からそのまま呼べるので、
`tests/mp4.mjs` がブラウザを起こさずに検証しています。新しく算数だけの部分を書くなら、
同じように分けてください。

## 5. スタジオの設計で、外してはいけない4点

1. **持つのはマット（濃さ1枚）だけ。** 仕上がりの絵を全部持つと 880MB になります。
   元の絵は、見せるときも書き出すときも `<video>` から取り直します。
2. **仕上げ（フチ削り・ぼかし・色抜き）は、描画の直前にかける。**
   マットを書き換えないので、つまみを動かした瞬間に絵が変わります。
   ここを「処理のときに焼き込む」形に変えると、つまみ1つで数分待つ道具になります。
3. **書き出しは実時間**（PNG連番を除く）。`MediaRecorder` だけが canvas の透明を
   保てるためです。だから「画面を離れたら止める」が要ります。
4. **いちどに引き受ける長さに上限がある**（`budget.ts`）。上限を外すと、
   長い動画でメモリを使い切って**タブごと落ちます**（いちばん最悪の壊れかた）。

## 6. 実際に踏んだ落とし穴

同じ穴を掘り返さないための一覧です。どれも検証に項目が残っています。

| 症状                                            | 原因と対処                                                                                                             |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| プレビューが1コマ目で止まる／書き出しが返らない | DOM に入っていない `<video>` には `requestVideoFrameCallback` が来ない。画面の外に 2px で置く（`display:none` は不可） |
| 動画の長さが 0 になる                           | 録画ソフトが作った WebM には長さが書かれていない。`currentTime = 1e101` で終わりへ飛ばして確かめる                     |
| 「録れる形式」と言われたのに書き出しで落ちる    | `isTypeSupported` は嘘をつく。実際に `MediaRecorder` を組み立てて確かめる                                              |
| 書き出した動画が途中から止め絵                  | 画面が隠れるとコマ送りが止まる。隠れたら録音機ごと止め、戻ったら繋ぎ直す。**はじめから隠れている場合**も見る           |
| 再開後に同じコマが二重に入る                    | 止める前の予約は取り消せない。世代番号を持たせて古い予約を降ろす                                                       |
| 音だけ先に進む                                  | 録音機を先に回さない。**1コマ目を渡せるようになってから**録りはじめる                                                  |
| 素材を替えたら、まるごと消えた                  | 前の素材で選んだ「消しかた」が残っていた。素材を置きなおしたら見立てからやり直す                                       |
| スマホで右がはみ出す                            | グリッドの子は既定で縮まない。`min-width: 0` を置く                                                                    |
| シートだけ色が違う                              | `Sheet` は `body` 直下に出る。色は `body.studio-theme` に持たせる                                                      |
| 緑の地から抜くとフチが緑に光る                  | 色かぶり（不透明な画素）＋圧縮のにじみ。「緑が赤と青の平均を超えた分」を削り、クロマキーのときは境目の幅を広げる       |

## 7. 検証の考えかた

**「目で見ないと分からない」と思われることを、数で見る**のがこのリポジトリの方針です。

- 透過の良し悪し → 出力画素のアルファを読む（四隅・まん中・半透明の割合）
- 書き出したファイル → **開き直して**、すみが透明か・緑が塗られているかを読む
- 音 → 書き出しを `decodeAudioData` して、鳴っているか・絵とずれていないかを測る
- iPhone → 名乗り（User-Agent）と分かれ道の入口だけ置き換えて、どちらへ行くかを見る
- 算数だけの部分（`glow.ts` / `budget.ts` / `mp4.ts`）→ Node で直接呼ぶ

**機能を足したら、検証も足してください。** 足す場所は
`tests/run.mjs`（画面と書き出し）か `tests/mp4.mjs`（算数）です。
検証用の絵は `tests/fixtures.mjs` がその場で描き起こします
（本物に似せるのではなく、**つまずく性質だけ**を取り出して作る）。

## 8. いまの状態と、次の一手

### 出来ていること

- つくる画面（3ステップ）は完成。実機での保存まで検証ずみ
- スタジオ（`#/studio`）は、置く→けす→使う が通しで動く。
  透過WebM・グリーン・PNG連番・背景つきの4つの出口、iPhone の分岐、
  黒い地の光もの、離席対策、長さの上限まで入っている
- 検証 300件以上。`npm test` 一発で全部走る

### まだ確かめられていないこと（引き継いだ人にお願いしたい）

1. **AI 切り抜きの実地確認。** 開発環境が huggingface.co を遮断しているため、
   モデルの取得から推論までを一度も通せていません。**実機で一度確かめてください。**
   見るところ：フチの精度／1コマあたりの時間／WebGPU が無い端末での速さ。
2. **iPhone 実機での保存。** 共有シートに「ビデオを保存」が出るか、
   写真アプリに入るか。分岐の設計は入っていますが、実機は未確認です。
3. **長い素材・大きい素材での書き出し。** 上限は計算で置いていますが、
   実機のメモリで確かめていません。

### 次にやるとよさそうなこと（優先順）

1. **動画向けの切り抜きモデルを検討する。** いまは静止画向けのモデルを
   1コマずつ走らせています。動画向けのもの（前のコマの状態を持つ種類）に替えると、
   速さもゆれの少なさも一段良くなる可能性があります。
   ライセンス（商用可否）と、ブラウザで動く形（ONNX）があるかを先に確かめること。
2. **縦（9:16）に整えて書き出す。** TikTok に重ねる素材は縦が多いので、
   切り抜きを縦の画面に配置して書き出せると手数が減ります。
3. **スタジオの使いかたページ。** つくる画面には「これ、どう使うの？」に答える
   仕掛けがありますが、スタジオにはまだありません。
4. **PR を出す。** 作業は `claude/video-image-background-removal-h858og` に
   積んであります（未マージ）。

## 9. 作業のループ

```bash
# 1. 直す
# 2. 型と整形
npm run typecheck && npx prettier --write "src/**/*.{ts,tsx,css}" "tests/*.mjs" "*.md"
# 3. 配るものを作って、検証を通す
npm run build && CHROMIUM_PATH=... npm test
# 4. 配るものの中身も見る（禁止語・重さ・残りかす）
node tools/check-dist.mjs
```

コミットの文には、**何を変えたかより「なぜそうしたか」**を書いてください。
このリポジトリの履歴は、そのつもりで書かれています。
