# フレームを配って、みんなの見た目をそろえる（計画）

**やりたいこと**（相談のことば）

> アイコンフレームを登録して、それをみんなに共有して、固定されたアイコンフレームに
> 自分が持っている画像を配置できるようにしたい。
> みんなアイコンフレームつける時にバラバラになっちゃうことを懸念して。

この文書は、まだ何も作っていない段階の計画。**何を、どの順番で、なぜその順番か。**

---

## 0. 「バラバラになる」の中身は、2つある

ここを分けないと、作るものを間違える。

| 何がバラバラになるか       | いまの状態                                                 |
| -------------------------- | ---------------------------------------------------------- |
| **① 違うフレームを使う**   | 半分解決ずみ（「とうめいにしたフレームだけを保存する」がある） |
| **② 同じフレームでも置きかたが違う** | **1つも手を打っていない**                          |

### ② のほうが、原因として大きい

いまの3つめの画面（`ComposeStudio`）は、こうなっている。

```
写真  … 画面いっぱい（cover）から始まる
フレーム … 全体が入る（contain）から始まる
そのあと … 指で自由に動かす・大きさ・かたむき・左右反転
ほかに  … 写真のかたち（そのまま/まる/かどまる/しかく）
          すきまの色（とうめい/白/黒）
          まるく切りぬく（入/切）
```

**始まりの位置は全員同じでも、そこから全員が別々に動かす。**
しかも「指でうごかす／2本でひろげて大きさ」と画面が誘っているので、動かすのが普通。

その結果、同じフレームを配っても、
「顔が小さい人・大きい人・ずれている人・かたむいている人」が並ぶ。

**つまり、配るしくみを作っても ② を直さなければバラバラのまま。**
逆に ② を直すと、**いまの手渡し（PNGを配る）だけでも そろう。**

だから順番は ② が先。

## 1. 段階0 —— 写真を、フレームの穴に自動で合わせる

**共有のしくみを1つも作らずに、いちばん効く。**

### すでに、穴の場所は分かっている

`src/lib/cutout.ts` の `floodBackground` は、背景を消すときに
**画像の中心からも種を蒔いている**。リング状のフレームの「まん中の穴」を
抜くためで、そうしないと重ねたときに写真が隠れるから。

```
種は2か所から蒔く。
 - 画像の四辺 … 外側の背景
 - 画像の中心 … リング状フレームの「まん中の穴」
```

つまり**穴がどこにあるかは、背景を消した時点で計算できている**。
捨てているだけ。これを持ち越して、写真の初期位置に使う。

### やること

1. 背景を消したあと、**穴の外接する円（または矩形）**を求めて持ち回る
   - 中心 `cx, cy` と半径 `r` を、フレーム画像に対する**比**で持つ（画素で持たない）
2. 3つめの画面の初期値を、cover ではなく**その穴にぴったり入る倍率・位置**にする
3. 穴が見つからないフレーム（リングでないもの）は、いままでどおり cover

### これで何が変わるか

- **ほとんどの人が、もう動かさなくてよくなる。** 動かさなければズレない
- 動かしたい人は、いままでどおり動かせる（取り上げない）
- 手渡しでPNGを配っている人たちにも、その日から効く

### 気をつけること

- 穴が細長いフレーム（縦長の窓など）で、丸く切りぬくと角が出る。
  穴の形（縦横比）も一緒に持って、写真のかたちの初期値を決める
- 「まるく切りぬく」の初期値と食い違わせない

## 2. 段階1 —— フレームを配る（リポジトリに入れる方式）

段階0 のあとに。**ここで初めて「共有」になる。**

### 配りかたの選択肢（4つ調べた）

| 方式                                   | サーバー | 登録できる人 | 判定             |
| -------------------------------------- | -------- | ------------ | ---------------- |
| **A. リポジトリに入れて配る**          | 要らない | 運営だけ     | **これを推す**   |
| B. リンクの中に画像を全部入れる        | 要らない | 誰でも       | 実用にならない   |
| C. 作った人が自分で置いたURLを指す     | 要らない | 誰でも       | 穴が多い         |
| D. 保存所を借りる（Supabase / R2 など）| 要る     | 誰でも       | 別の事業になる   |

#### B を落とす理由（実測）

フレームのPNGは実測 **30〜270KB**。base64 にすると 1.33倍で **40〜360KB のURL**になる。

- ブラウザは開ける（ハッシュはサーバーへ送られないので長くても通る）
- **しかし LINE・X・Discord に貼ると切れる**
- QRコードの上限は約3KB。桁が2つ足りない

256px まで落とせば20KB程度に収まるが、書き出しは900pxなので**ぼやけたフレーム**になる。
**貼って配れないリンクは、共有機能として意味が無い。**

#### C を落とす理由

- 置いた先が消えたらフレームも消える（リンク切れ）
- CORS が通らない置き場所が多い
- **URLに何でも書ける。** 他人の画像や、まったく別のものを
  「このツールのフレーム」として開かせられる

#### D を選ばない理由（いちばん大事）

これは**プラットフォームになる**という話。

誰かが他人のキャラクターのフレームを登録した瞬間、
**あなたが置き場所を提供したことになる。** 必要になるのは、

- 権利者からの連絡を受ける窓口
- 通報と削除の手順（プロバイダ責任制限法）
- 登録されたものを見る人（自動では無理）
- 費用（保存所・通信）

そして、**いまこの口座はお礼（チップ）を受け取っている。**
「無料で配っているだけの個人」と「金銭を受け取りながら他人の著作物が集まる場所を
運営している個人」は、話の重さが違う。

Stripe の件（`docs/stripe-compliance.md`）で踏んだのと**同じ種類の穴**。
あのときの教訓は「**先に聞く。黙って始めない**」だった。

→ **D をやるなら、それは ae-Frame の機能追加ではなく、別の事業として設計する。**

#### A を推す理由

- いまの作り（サーバーを持たない・静的配信）に**そのまま乗る**
- 1枚ずつ目で見てから入れるので、権利の問題が起きにくい
- **そもそも、やりたいことに足りている。**
  「うちのコミュニティの公式フレーム」は **1枚**あればいい。
  誰でも登録できる必要が、いまは無い

### 段階1 でやること

```
public/frames/<id>.png     … 背景を消したフレーム（運営が入れる）
public/frames/index.json   … どんなフレームがあるか
```

`#/f/<id>` で開くと、こうなる。

```
いま       ① 写真をえらぶ → ② フレームの背景をけす → ③ 位置をあわせて保存
共有リンク ① 写真をえらぶ →                        → ② 位置（固定）→ 保存
```

**背景けしの画面が丸ごと要らなくなる**（もう透過ずみなので）。
3ステップが2ステップになる。配られた人にとっては、いまより簡単になる。

### 「固定する」の中身

フレームに**レシピ**を添える。画像だけ配っても、置きかたは固定されない。

```json
{
  "id": "yourname-2026",
  "name": "○○フレーム",
  "hole": { "cx": 0.5, "cy": 0.5, "r": 0.34 },
  "lock": {
    "move": "hole",
    "rotate": false,
    "gap": "white",
    "round": true
  }
}
```

| 鍵       | 意味                                                       |
| -------- | ---------------------------------------------------------- |
| `hole`   | 写真を入れる窓。フレーム画像に対する**比**（画素で書かない）|
| `move`   | `hole`＝穴の中でだけ動かせる／`free`＝自由／`none`＝動かせない |
| `rotate` | かたむきを触らせるか                                       |
| `gap`    | すきまの色を固定する                                       |
| `round`  | まるく切りぬくを固定する                                   |

**全部を禁止しない。** 顔の位置合わせ（穴の中での移動と拡大）は残す。
そこを取り上げると、顔が切れた人が直せなくなる。
そろえたいのは**フレームの見え方**であって、中身の人ではない。

### 引っかかること —— 画像の重さの上限（実測で確認ずみ）

いまの検証は、配る画像の合計に上限を持っている。

```
配る画像の合計が上限に収まっている   743.8 KB / 上限 850 KB（13 枚）
```

**余白は106KBしかない。フレームを2〜3枚入れた時点で `npm test` が落ちる。**

上限を上げて済ませてはいけない。上限の趣旨は
「スマホしか持っていない人が前提の道具なので、初期表示を重くしない」。

フレームは **`#/f/xxx` を開いた人だけが要るもの**で、初期表示には要らない。
だから数えかたを分ける必要がある。

```
初期表示に要る画像          … いまの上限のまま（850KB）
求められたときだけ取る画像  … 別に数える（1枚あたりの上限だけ持つ）
```

`tools/check-dist.mjs` の変更。**上限を上げるのではなく、種類を分ける。**

### 約束の文面は、変えなくてよい（確認した）

> 画像はこの端末の中だけで処理されます。どこにも送信されません

フレームを**取りにいく**のは通信だが、送っているものは1つも無い。
利用者の写真はこれまでどおり端末から出ない。**この文のままで正しい。**

ただし、配られたフレームを開いた画面には
「このフレームはインターネットから読み込みます」と**足す**（隠さない）。

## 3. 段階2 —— 誰でも登録できるようにする（いまは決めない）

段階1 を配って、**実際に「自分のフレームも置きたい」という声が出てから**考える。

出てこなければ作らない。
出てきたら、そのときに 2.D の表（窓口・削除手順・費用・人手）を上から確認する。

**先に作らない理由**は、要るかどうか分からないものに
「他人の著作物が集まる場所の運営」という重い責任を先に背負うことになるから。

## 4. 順番と、それぞれの大きさ

| # | やること                                     | 大きさ | 共有機能が要るか |
| - | -------------------------------------------- | ------ | ---------------- |
| 1 | **穴に自動で合わせる**（段階0）              | 中     | **要らない**     |
| 2 | 画像の数えかたを「初期表示／あとで取る」に分ける | 小  | 段階1の下ごしらえ |
| 3 | `#/f/<id>` のルートと、フレームの置き場所     | 中     | —                |
| 4 | レシピ（`hole` / `lock`）を効かせる          | 中     | —                |
| 5 | 配られた人の画面（2ステップ）                | 中     | —                |
| 6 | フレームを1枚入れて、実際に配ってみる        | 小     | —                |

**1 だけ先に出せる。** 2〜6 は段階1としてまとめて出す。

## 5. 検証で見ること（作る前に決めておく）

この道具の決まりごととして、**足した検証は必ず1つずつ壊して、落ちることを確かめる。**

段階0

- 穴のあるフレームで、写真が**穴にぴったり**入っている（はみ出しも余りもしない）
- 穴の無いフレームでは、いままでどおり cover から始まる
- 初期状態から**一度も触らずに保存**したものが、2回やって1画素も変わらない

段階1

- `#/f/<id>` を開くと、**背景けしの画面を通らない**
- 固定した項目が、画面に**出ていない**（出ていて押せないのが、いちばん困る形）
- 知らない `<id>` を開いても、行き止まりにならず、つくる画面に落ちる
- 同じフレーム・同じ写真で、**違う端末から保存したものが一致する**
  （これが「そろう」の定義そのもの。ここを数えないと、そろったか分からない）
- 初期表示で、フレームの画像を**1枚も取りにいっていない**
