# Stripe 側でやること（渡す用）

サイト側の実装は**もう入っている**。決済リンクを1本もらえれば、
GitHub の設定を1か所いじるだけで出る。ここは、その1本を作る手順。

> **順番を守る。** 先に Stripe に聞いて、返事をもらってから作る。
> 一度「規制対象業種のいずれかに関連する」と判断された口座なので、
> 黙って再開しない（`docs/stripe-compliance.md`）。

---

## 0. いま何が出来ているか

| いまの状態               |                                               |
| ------------------------ | --------------------------------------------- |
| お礼のページ（`#/tip`）  | 実装ずみ。**配るものには入っていない**        |
| つくる画面の足もとの入口 | 実装ずみ。同上                                |
| 決済リンク               | **0本**。作っていない                         |
| 出すためのスイッチ       | GitHub のリポジトリ変数 `TIP_URL`（いまは空） |

`TIP_URL` が空のあいだ、お礼の文言は**1文字も配られない**。
条件分岐で隠しているのではなく、ビルドの時点でモジュールごと入らない。
検証がそれを毎回読んで確かめている。

---

## 1. まず Stripe に聞く（リンクを作る前）

サポートに、この内容で問い合わせる。**書面で聞いて、書面で返事をもらう。**

### 送る文面のたたき台

> アイコン画像を作るブラウザツールを個人で公開しています（URL: <公開URL>）。
> 全機能が無料で、有料の機能・サブスクリプション・販売する商品はありません。
> 画像処理はすべて利用者の端末内で完結し、当方のサーバーはありません。
>
> このツールを**すでに使っていただいたことに対する任意のお礼（チップ）**として、
> 金額を利用者が決める支払いを受け付けたいと考えています。
>
> - 支払っても、機能は1つも増えません
> - 支払わなくても、全機能がそのまま使えます
> - 特典・限定公開・先行公開など、お返しするものは一切ありません
> - 今後の制作物や資金使途については、ページに一切記載しません
> - 目標金額・募集期間・支援者一覧も置きません
>
> 実際に掲載する文面は下記のとおりです。
>
> （↓ 第2節の全文を貼る）
>
> この形で Payment Links を利用して差し支えないか、ご確認をお願いします。
> あわせて、利用すべき商品（Payment Links / Checkout など）や、
> 掲載すべき表示事項の指定があればご教示ください。

### 併せて確認しておきたいこと

聞きかたを1段変える。「寄付かチップか」だけだと**分類の話**に見えて、
返事も分類で返ってくる。**要件に当たっているか**を聞く。

> 本件は、Stripe の定める「**すでに提供した商品・サービスに対するチップ**」の
> 要件に該当するという認識でよいでしょうか。

- 過去に照会を受けた件について、**現在は解決済みであり**、この用途で
  Stripe Payments を利用して問題ないという理解でよいか
  （ここはアカウント個別の審査結果なので、公開情報からは判断できない。
  **書面で明文化してもらう**）
- 当方のアカウント区分でこの用途を利用できるか
  （日本の利用規約に「事業者でない個人（個人事業主でない個人）は、
  Stripe の事前承認がある場合にのみ利用できる」という条項がある）

**返事が来るまで、リンクは作らない。**

## 2. 実際に画面に出る文面（そのまま添付する）

```
作った人にお礼を送る

このツールはぜんぶ無料で使えます。
このツールをすでに使っていただいたことへの任意のお礼として、好きな金額を送れます。

【送っても、送らなくても、できることは1つも変わりません。】
払うと増える機能はありません。払わないと使えない機能もありません。
お返しするものもありません。

［ お礼を送る ］

金額を決める画面と支払いは、決済サービスの側でおこないます。
カードの番号は、このサイトを通りません。
```

この文面は `src/components/Tip.tsx` が正。**ここを変えたら、Stripe に出したものと
食い違う。**変えるときは、出した文面も差し替える。

食い違いは検証が見ている（`npm test` の「お礼の文面が、Stripe に出すものと同じ」）。
見張っているのは**この文書と `docs/tip-stripe-inquiry.md` の2か所**。
片方だけ直しても、枠ごと消しても、文書ごと消しても落ちる。

**断りの文を1行消すのも落ちる。** そこがいちばん危ない方向なので、
「消えては困る文」は `tools/check-dist.mjs` に別に並べてある
（画面・手順書・問い合わせ文の3つ全部に残っていること）。

### 「これからも無料のままです」を書かない理由

はじめ書いていた。やめた。将来の約束を1つ背負うだけでなく、
**払った人への見返りに読める**（払ったから無料が続く、という因果が立つ）。
見返りが1つでも立つと、そこから先は売りものの話になる。

逆に「**すでに**」と「**任意の**」は足した。Stripe がチップに求めるのは
「すでに提供した商品・サービスに対する支払い」で、この一文がその要件に
そのまま当たる場所だから。

## 3. 「可」の返事が来たら：Payment Link を1本つくる

ダッシュボード → 商品カタログ／Payment Links から。

### 値段の決めかた

| 項目           | 設定                                                   |
| -------------- | ------------------------------------------------------ |
| 価格モデル     | **顧客が金額を決める**（Customers choose what to pay） |
| 支払い回数     | **1回きり**。サブスクリプションにしない                |
| 通貨           | JPY                                                    |
| 既定額（任意） | 例：500円                                              |
| 下限（任意）   | 例：100円                                              |
| 上限（任意）   | 例：10,000円                                           |

> 「顧客が金額を決める」は**1回きりの支払い専用**で、定期課金には使えない。
> ちょうどよく、定期課金は今回やってはいけないほうなので、そのままでよい。

### Payment Link のタイトルと説明

ここでも「商品」と呼ばない。ずっと「販売するものではない」と整理しているのに、
内部の資料だけ商品と呼ぶ理由が無い。呼びかたが揺れると、書く言葉も揺れる。

- タイトル：`アイコンフレーム メーカーへのお礼`
- 説明：

```
すでに無料で公開しているツールを使っていただいたことへの、任意のお礼です。
お支払いによって増える機能や、お返しするものはありません。
```

**説明に書かないこと**（ここを外すと、また同じところで止まる）

- これから作るもの、今後の予定
- お金の使いみち
- 目標金額・募集期間・達成度
- 特典・限定・先行・支援者一覧
- 「支える」「続けられます」系の言いかた

### 詳細設定で気をつけること

- **ボタンの文言を「寄付する」に変えない。** Stripe には
  「支払う（pay）」から「寄付する（donate）」に変える設定がある。
  今回は寄付ではなく、**すでに提供したツールへの任意のお礼（チップ）**として
  整理している。「寄付する」という表示を使うと、実態と合わないうえ、
  寄付だと受け取られる。**既定の支払いの表現のままにする。**
  （押した瞬間に取引の分類が切り替わる、という話ではない。
  食い違いを自分から作らない、という話）
- 住所・電話番号の収集は**オンにしない**（要らないものを集めない）
- 支払い後の戻り先URLは**設定しない**。Stripe の既定の完了画面のままにする。
  こちら側にお礼ページを作らないのは意図的で、画面を増やすと消すときに忘れる。
- 数量の変更、クーポン、税の自動計算は、どれも要らない
- 明細に出る名前（statement descriptor）は、見て分かるものにしておく

## 4. 出来たリンクを、サイトに載せる

1. 発行されたリンクをコピーする（Stripe が出す `https://` で始まるURL）
2. GitHub の **Settings → Secrets and variables → Actions → Variables** タブ
3. `New repository variable`
   - Name: `TIP_URL`
   - Value: コピーしたリンク
4. 保存すると、次の公開から入口が出る（コードの変更は不要）

**secret ではなく variable に入れる。** 中身は誰でも見る公開URLで、
secret にするとログで伏せ字になり、取り違えたときに気づけない。

### 出したあと、目で確かめること

- 公開URLの足もとに「作った人にお礼を送る」が出ている
- 押すと `#/tip` が開き、「送っても、送らなくても…」が出ている
- そこから決済画面へ飛べて、**金額を自分で決められる**
- つくる画面（1〜3）に、お金の話が1文字も出ていない

最後の1つがいちばん大事。**払わない人が損をしない**というのが、この形の中身なので。

---

## 5. 止めるとき

`TIP_URL` を空にする（または変数ごと消す）。次の公開で、入口も文言も
配るものから消える。Stripe 側のリンクも合わせてアーカイブする。

---

## 6. サイト側では扱わないこと

- 返金：Stripe のダッシュボードから
- 明細・領収書：Stripe が出す
- 税：**金額が動く前に税理士に確認する。** 個人が受け取る任意の金銭は、
  金額と継続性しだいで扱いが変わる
- 特定商取引法：**見返りを1つも設けない前提**のため、通常の商品・サービスの
  販売とは異なる形として整理している。**ただし表示義務の要否をここで確定させていない。**
  必要に応じて、公開の前に専門家に確認する。
  前提が崩れる変更（払った人だけの機能など）を入れると、氏名・住所・電話番号の
  表示が要る話になる。詳細は `docs/tip-restart-plan.md`
