### いちばん効いた1件は、画像ではなくビルド設定でした

素材の話をしに来て、素材ではないものが最大の原因でした。**AI の実行環境
（transformers + onnxruntime、855KB）が、どのページを開いても落ちてきていました。**

`vite.config.ts` に「AI を1つの塊にまとめて、必要になるまで読み込ませない」という
`manualChunks` を書いていたのですが、その塊に Vite が動的 import のために使う
**200バイトほどの補助関数**まで一緒に入ってしまい、補助関数は入口の側から
ふつうに import されます。結果、入口が 855KB の塊を静的に参照する形になり、
`index.html` に `modulepreload` まで付いて、切り抜きの画面へ一度も行かない
**応援ページやお礼ページでも 855KB を先に払っていました**。

飾りの画像を全部足しても 690KB なので、**素材より大きい1件**でした。
まとめる指示を消したところ、動的 import は素直に別の塊へ分かれました。

この1件だけを外して測った値（飾りの調整を入れる前の時点）:

| ページ | まとめる指示あり | **なし** |
| --- | --- | --- |
| つくる | 1.11 MB | **0.28 MB** |
| 応援 | 1.67 MB | **0.83 MB** |
| お礼 | 1.54 MB | **0.71 MB** |

（第1節の表と数字が違うのは、あちらが飾りの調整まで入れた最終値だからです）

ページは前から正しく動いていたので、**見ても分かりません。測って初めて分かります。**
同じことが起きたら気づけるよう、検証に「開いただけで重いものを落とさない」を足しました
（1件400KB超を落とさない／最初の合計1MB未満）。

## 7. Background / Visual Recommendation

### 置きかたの方針

**「BLUE FRUIT LAB の世界観をサイト全面へ敷く」ではなく、
「静かで機能的な ae-Frame の余白へ、研究標本の気配だけを薄く置く」。**

守るもの: 生成り〜白の地 / 薄いグリッド / 細い黒線 / 赤い操作アクセント / 大きな余白 / 操作性優先
避けるもの: サイバーUI化 / ネオン広告化 / 宝石広告化 / キラキラ過多 / 紫主体 /
**全画面装飾** / **UIより装飾が目立つ状態** / 背景画像の大量追加

### ページごとの判断

| 画面 | 判断 | 置いたもの |
| --- | --- | --- |
| つくる（ステップ1〜3） | **装飾なし** | `body::before` の方眼（opacity 0.035）だけ。ここは**透過の結果を目で確かめる画面**なので、背景に色があると判断の邪魔になる |
| 応援ページ | **少量だけ** | 地（opacity **0.18**）＋ 左上に葡萄 ＋ 右下に水。**3枚まで** |
| お礼ページ | **地は画像を使わない** | CSS の `radial-gradient` 2本（0KB）＋ 右下に水 ＋ カードを縁取る水の輪 |

### 実画面に置いてから直したこと

**地（`.decor__bg`）を 0.5 → 0.18 に。**
0.5 で敷いたら、パソコンの画面がまるごと水色の紙になりました。
この道具の地は生成りで、その上に薄いグリッドが乗っているのが本体です。
そこが見えなくなった時点で、「気配を置く」ではなく「世界観を敷く」になっています。
0.18 まで落とすと生成りとグリッドが地のまま残り、端にだけうっすら水の色が差します。
スマホはさらに 0.14（画面が狭いぶん、同じ濃さでも密度が上がるため）。

中央を抜くマスクも広げました（半径 18% → 30%）。本文の下は生成りのままになります。

**葡萄（`.decor__fruit`）はお礼ページに出さない。**
お礼ページは短い文とボタン1つを読ませる場所です。角にもう1枚足すと、
読ませたいものの周りが飾りで埋まります。**250KB 軽くなりました。**

### 一度外して、置きかたを直して戻したもの — `support-celebration`（水の輪）

**最初は「この素材は使えない」と判断しました。それは間違いでした。**
使えなかったのは絵ではなく、こちらの置きかたです。

絵は**中央がまるく空いた輪**で、何かを囲むために描かれています。
それを `background-size: cover` で画面いっぱいに引き伸ばしていたので、
輪の左右の腕がパソコンの広い余白に散らばり、水の塊が並んでいるように見えていました。
「UIより目立つ」「広告っぽい」と判定したのは、その状態のことです。

直した順番も記録しておきます。1回では当たりませんでした。

| | やったこと | 何が起きたか |
| --- | --- | --- |
| 1 | 画面いっぱい（cover / opacity 0.34） | 輪の腕が余白に散らばる。**不採用と判断** |
| 2 | 本文の列に合わせる（top 0） | 腕は収まったが、輪の濃いところが**ステップ表示（1・2・3）に重なり**「完了」が泡に埋まる |
| 3 | 開始をカードの上端へ（top 132px / 幅 +130px） | ステップ表示は読めるようになったが、輪の中央がカードに隠れ、**左右に水の塊が2つ浮いて見えた** |
| 4 | 広げて薄くする（幅 +300px / opacity 0.46 → 0.34） | カードを囲む輪として成立。**採用** |

いまの形:

```css
.decor__celebration {
  top: 132px;                                   /* = カードの上端 */
  width: min(calc(var(--page) + 300px), 98vw);  /* 画面幅に連動させない */
  opacity: 0.34;                                /* 広げたぶん薄く */
  mask-image: linear-gradient(black 52%, transparent 88%);  /* 下側は消す */
}
```

**大きさと濃さは、片方だけ上げること。** 両方上げるとただの広告になります。
スマホは 130vw / 0.30（カードが画面いっぱいなので、見えるのは上の弧だけ）。

判断軸に照らすと:

| 軸 | 画面いっぱい（1） | **いまの形（4）** |
| --- | --- | --- |
| UIより目立っていないか | ✗ PCで左右が埋まる | ○ カードの縁だけ |
| テキストを邪魔していないか | △ | ○ 飾りの層は本文より後ろ |
| CTAを邪魔していないか | △ | ○ |
| ステップ表示が読めるか | ✗（2で発覚） | ○ |
| BFL感が出ているか | ○ | ○ |
| 広告っぽくなっていないか | ✗ 大きなガラスが並ぶ | ○ |
| モバイルで過密でないか | ○ | ○ カードの後ろにほぼ隠れる |
| 輪として読めるか | ✗ 塊に見える | ○ |

**教訓**: 素材の良し悪しと、置きかたの良し悪しは別のもの。
1つの置きかたで悪く見えたことを、素材の判定にしてしまっていました。

### 機械で見張っていること

見た目の良し悪しは測れませんが、**そうなる手前の条件**は測れます。
検証（`tests/run.mjs`）に足しました。

- 画面を覆う画像の層は、**薄い地の1枚まで**（opacity 0.25 以下）
- 端の飾りは**画面の面積の2割まで**
- お礼ページは**地の画像を取りに行かない**
- **水の輪の大きさが、画面の広さで変わらない**（最初の失敗そのもの）
- **水の輪がステップ表示にかからない**（2番目の失敗そのもの）
- 水の輪が本文の列から左右に出るのは、あわせて 360px まで
- 動きを減らす設定の人には、飾りを動かさない
- 開いただけで 400KB を超えるものを落とさない／最初の合計が 1MB 未満

地の opacity を 0.5 に戻すと、これは実際に落ちます（確認済み）。
輪の2件は、実際に踏んだ失敗をそのまま条件にしてあります。

### CSS / SVG だけで済ませているもの

- **お礼ページの地** — `radial-gradient` 2本 / 0KB。暗いテーマにも自動で追随
- **ヘッダー／フッターのロゴ** — 既存の `IconFrame`（線画SVG）
- **方眼** — `body::before` の 28px 格子（opacity 0.035）。これが「制作グリッド」そのもの

円弧・アンカーポイント等の「制作の痕跡」は方向としては合いますが、
**いまは水と葡萄が既に入っているので足すと過密になります。推奨: 追加しない。**
